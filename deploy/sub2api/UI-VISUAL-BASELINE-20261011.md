# 调用记录与筛选：视觉探底（2026-10-11）

状态：调研完成，建议尚未实施；生产保持 UX5。本轮没有服务重启、发布、数据迁移或模型调用。

## 结论

当前记录页有明确优化空间。差异按影响排序是：筛选/统计的组织方式、每行信息层级、手机展示方式、字号字重与数字排版，最后才是阴影。单纯加阴影或换字体不能恢复旧版体验。

当前 `/usage` 与 `/admin/usage` 都使用迁移时新增的 `RealYuUsageView.vue`。原生 Sub2API 的记录页位于 `/usage/diagnostics` 与 `/admin/usage/diagnostics`。因此此次发现描述的是 RealYu 自定义展示层，不能据此认定 Sub2API 内核或全部原生页面质量较差。

旧 RealYu 前端的调用记录已有常用/高级筛选、紧凑统计条、移动筛选抽屉、移动记录卡片和统一表格组件。这些设计未完整迁入当前简化记录页。

## 实测差异

下列数值来自本轮运行 DOM 与组件样式定义；桌面对比均为 1280×720。行高与字段数量相关，不用行高单独判断优劣。

| 项目 | 当前 RealYu / Sub2API 自定义页 | 旧 RealYu / New API 前端 | 判断 |
|---|---|---|---|
| 筛选输入框 | 约 43.3px，额外可见标签行 | 32px，日期范围合并成一个入口 | 当前更像表单，旧版更像查询工具条 |
| 统计展示 | 三张卡片，高约 73.3px | 28px 紧凑统计条，置于筛选面板内 | 当前占据过多纵向面积 |
| 表头起点 | y≈329px | y≈272px | 当前晚约 57px 才到表格 |
| 表格字号 | 14px / 20px 行高 | 13px / 约18.6px 行高 | 旧版视觉更紧凑，不能全站一律缩小 |
| 时间主文字 | weight 400，灰色 `#374151` | weight 500，接近黑色 | 当前主数据不够突出 |
| 单元格内边距 | 12px 上下、16px 左右 | 8px | 当前单层信息周围空间偏多 |
| 一条记录行高 | 约52.7px | 60px，多处两层信息 | 旧版并非靠矮行取胜，而是单位面积信息组织更好 |
| 数字 | 当前 Token/费用为普通数字、左对齐 | 共用表格定义有 `tabular-nums`，部分统计使用等宽字体 | 应统一金额与 Token 的对齐和数字宽度 |
| 输入框阴影 | none | none | 阴影不是输入框质感差异的主要原因 |
| 卡片阴影 | 当前 `.card` 全部取消；外框仅极浅阴影 | 面板、统计条有选择地使用轻边框/微阴影 | 只修复层级，不建议加大面积强阴影 |
| 手机表格 | 宽≈874px，费用列 x≈720px；首行 y≈659px | 记录改为卡片，模型和费用同屏 | 手机卡片与折叠筛选是优先项 |

字体配置也不同：旧版 CSS 声明 `Public Sans, sans-serif`，当前为 `system-ui` 加 Windows/macOS/CJK 回退。旧编译包的字体文件实际声明名是 `Public Sans Variable`；不能从 CSS 名称直接证明浏览器使用了 Public Sans，更不能断言中文来自该拉丁字体。本轮没有逐字形字体解析证据。建议先统一字号、字重、数字特性，再用同一设备确认是否需要引入/修正字体文件。

## 建议落地范围

### 第一批：只改记录页，收益最高

1. 常用筛选保留“时间范围、模型、用户”；管理员高级条件收进“更多筛选”，有已用条件时显示数量。日期合并一个范围入口，加入今天/近7天/近30天；保留可访问名称，不能只靠 placeholder。
2. 保留当前“实际消费、调用次数、Token用量”的业务定义，将三张大卡改成一排紧凑统计条，和筛选构成一个整体。不要因抄旧视觉把累计请求数误换为 RPM/TPM。
3. 桌面按“时间 / 模型 / 用户ID / 昵称 / 使用范围 / Token / 费用 / 详情”组织，遵守此前 ID 与昵称分列要求。费用与 Token 对齐；金额用等宽数字，主数据 500 字重，辅助说明 12px。表头和分页保持可定位。
4. 需要回补输入/输出、缓存、耗时等信息时，在已有列的次级行或详情展示，避免所有诊断字段平铺。历史缺失字段继续显示“未提供”，不可补成 0。
5. 手机以“模型 + 人民币费用”为卡片第一行，下方放时间、昵称、用量；日期常驻，其余筛选进入抽屉。核心字段无需横滑；ID 可在明确的辅助位置或展开详情中读取。

### 第二批：统一公共视觉规则

- 保留现有 RealYu 蓝色和中性底色；主按钮、选中态使用蓝色，异常状态保留语义色。不要复刻旧版随机彩色头像和每行绿色“消耗”。
- 桌面密集工具条统一 32–36px 控件高度；手机仍保留舒适点击区域，不把所有控件缩到桌面尺寸。
- 表格 13–14px、主要数值/名称中等字重、次级说明 12px；页面标题18–20px。强调层级，不增加全局字号种类。
- 输入框、按钮、标签按用途定义尺寸，避免仅用全局 `.btn/.input` 覆盖；圆角保持旧版方向，但别让每个字段都像独立的大卡片。
- 以一像素边框、浅色表头和轻 hover 建立层次；必要处才加微阴影。旧版也不是重阴影风格。

实现目标应是把旧组件的布局/样式规则移植到 Vue 展示层。旧版为 React/TanStack，新版为 Vue，不适合直接 cherry-pick JSX 或同时引入第二套前端运行时。无需替换 Sub2API 内核、账本、鉴权、接口或数据库。

## 后续实现必须通过的验收

- 同样的1280/1440桌面和390手机对照；首屏核心记录可见，手机无需横滑看到模型、费用、昵称；长昵称、长模型、六位小额费用不挤压。
- 同一接口响应在修改前后：总费用、调用数、Token、分页一致；人民币显示精度、历史字段缺失与日期北京时间语义保持。
- 常用/高级筛选应用、重置、分页、浏览器前进后退、团队切换；加载、空结果、错误重试；不能仅截图绿就算通过。
- 管理员/团队管理员/普通成员/无团队用户的范围和权限保持；团队ID与昵称展示不恢复成旧版重复成员行。
- 中文/英文、明暗主题、桌面/手机；200%缩放、键盘焦点、抽屉关闭后焦点回归、表格与输入框可访问名称、实际对比度。
- 视觉变更先在隔离候选上检查，再按既有发布流程执行；这份调研不代表上述测试已通过。
