## 非验收账号的实际调用

排除此次发布专用的两个验收账号后，固定窗口内共 **112 条调用消费记录**，
来自两个记账主体，均为 `gpt-6-astra` / `/v1/responses` / 新 channel 4：

| 流式终态 | 条数 | 账务与诊断 |
| --- | ---: | --- |
| completed | 106 | 输入、输出、缓存 token 与 Sub2API usage 逐条一致，106/106 匹配 |
| client_gone | 5 | 客户连接提前断开，按本地估算结算；Sub2API 后来取得最终 usage，存在未对齐差异 |
| failed | 1 | 上游 HTTP/2 `INTERNAL_ERROR; received from peer`，客户 quota=0，随后有正常完成请求 |

`client_gone` 不能单凭日志区分主动取消、客户端退出和网络中断。五条估算记录
分别有匹配的 Sub2API 最终 usage，说明可以建立后续核对链路；当前没有自动完成
该链路。不要把不同阶段的生成量差异直接认定为固定比例的多扣或少扣。

窗口内没有相同 request_id 的重复消费记录，没有 type 5 错误日志，但这**不能**
等价为零失败：上述 SSE failed 以 HTTP 200 开始，失败终态保存在消费日志中；
Sub2API ops_error_logs 对应内部 502。成功请求的 token 对齐也不替代全部历史
客户资金的总账审计。现有活跃钱包/有限额 token 未发现负余额。

公网首次用默认 Python User-Agent 探测得到 403；使用已发布客户端的
`Realyu-Setup/1.0` 得到 200 及正确版本。保留两次结果，不将默认探测的拒绝计作
已证实的全站故障。未认证的公网管理接口保持拒绝，Sub2API 原生管理路由没有
通过 RealYu 公网入口直接暴露。
